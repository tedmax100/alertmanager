Alertmanager 架構設計與 Rancher 整合指南

长图

答

结论

Alertmanager 透過無中心 Gossip 叢集實作「Fail-Open」高可用性，並結合 Prometheus Operator 提供宣告式多租戶告警管理。

  1. 依據標籤計算 GroupKey，透過三個計時器達成告警聚合降噪。
  2. Memberlist 協議在節點間同步 nflog 去重日誌與靜音資料。
  3. 節點位置排序偏置等待時間，先發者廣播發送紀錄防止重複。
  4. Rancher 藉由 CRD 強制注入 namespace 標籤實現專案級隔離。

适用于Alertmanager v0.27+Rancher Monitoring v2HA Gossip

1

告警管線如何完成路由匹配與分組發送？

图的结构
  • 接收告警 rcv
  • 遍歷路由樹 tree
  • 計算 GroupKey aggr
  • group_wait 緩衝 wait
  • 抑制與靜音過濾 filter
  • nflog 去重檢查 dedup
  • 調用端點發送 send
  • aggr → wait · 存入 store
  • dedup → send · 首次發送
  • filter → dedup · 未被靜音
  • rcv → tree · POST /alerts
  • tree → aggr · 命中路由
  • wait → filter · 觸發 flush
  1. 接收告警 ↗

    Prometheus 透過 HTTP POST 推送活躍與恢復告警。

  2. 遍歷路由樹 ↗

    以 DFS 深度優先比對標籤，支援 continue 多路轉發。

  3. group_wait 緩衝 ↗

    新群組等待設定時間，聚合突發的多筆關聯告警。

  4. 抑制與靜音過濾 ↗

    依據 inhibit_rules 與 Silence 規則剔除衍生告警。

  5. 調用端點發送 ↗

    經由 nflog 去重驗證後，調用 Webhook 或 PagerDuty。

無中心 HA 叢集如何杜絕重複通知？

图的结构
  • Prometheus prom
  • Alertmanager 0 am0
  • Alertmanager 1 am1
  • Slack slack
  • prom → am0 · 推送告警
  • prom → am1 · 推送告警
  • am0 → slack · HTTP POST (發送通知)
  • slack → am0 · 200 OK
  • am0 → am1 · 廣播 nflog 紀錄 (:9094)
  • am1 → am0 · 狀態校驗 (t=15s)
  • am0 → am1 · 已發送 (靜默攔截)
  1. 多播直連 ↗

    Prometheus 同時將告警推送到叢集所有節點。

  2. 階梯等待 ↗

    節點依名稱排序計算等待時間：Position 乘以 15 秒。

  3. 先發廣播 ↗

    節點 0 等待 0 秒立即發送，並透過 Gossip 廣播日誌。

  4. 接替去重 ↗

    節點 1 等待 15 秒醒來，查驗日誌確認已發送即拋棄。
